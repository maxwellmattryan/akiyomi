# 1.0.0 — "From scouting to deciding"

Status: Draft · Target: spring 2027 (to be set after the MVP launch) · Last updated: 2026-10-21

## One line

> Akiyomi becomes the place an akiya buyer lives while they're seriously looking: paid reports they trust, the true cost after subsidies, towns as well as houses, and a Scout agent that keeps working between visits.

## What changes from the MVP

The MVP proves the loop: goal → plan → shortlist → trip → approved inquiry. 1.0 makes each part deep enough to pay for, and makes the agent **long-running**: it reads replies, re-plans when a house sells, and nudges the user when something worth their time appears.

| Capability | MVP (0.1) | 1.0 |
| --- | --- | --- |
| Geospatial | Hazard overlays, map, day clustering, drive times | Isochrone search ("within 60 min of Nagano Station by train"), town boundaries and profiles, legal-zoning layers, multi-prefecture data |
| Memory and user model | Single-user profile, learned preferences, editable memory | Household profiles (two people, merged and conflicting preferences), preference decay and "still true?" check-ins, explanations of which memories shaped each result, post-visit debriefs |
| Multi-step planning | One Scout, one trip, re-plan on step failure | Long-running Scouts driven by events (reply received, listing sold, price drop), multi-trip plans, follow-ups |
| Messy external APIs | Lodging, flights, routing, geocoding | Plus reply parsing (Japanese email), subsidy PDFs, open data for towns (census, clinics, schools, broadband), calendar sync, payments |
| Acting on the user's behalf | Send approved inquiries, export calendar | Read and act on replies (with approval), propose follow-ups, sync viewings to the user's calendar, prepare bookings for user-completed checkout, spend caps and a permissions page |

## Scope

### Paid property report

- Legal flags: urbanization control area, use zoning, agricultural land, frontage-road heuristics, with the rule and source cited.
- Structure detail (1981 and 2000 standards and what they mean for loans, insurance and tax deductions), utilities, land and boundaries.
- Bilingual questions for the seller and town hall, with why each matters.
- PDF export and a private share link.
- **Paste any URL:** an outside listing gets the same report.
- **Payments:** single report (~$29) and a 3-month buyer pass (~$99), via Stripe. Free tier keeps the map, hazard badges and one Scout.

### Money

- Subsidy matcher: municipal grant PDFs extracted into an eligibility rules table, refreshed each fiscal year; matched against the user model (age, household, relocation intent).
- Subsidy stacking across town, prefecture and national programs; net cost after grants.
- All-in purchase cost and yearly running costs; prices shown in the user's currency.
- Rough renovation range by level (livable / comfortable / showcase), labelled as rough.

### Towns and discovery

- Town profiles: population trend, hospitals with ER, clinics, schools, snow, broadband, foreigner friendliness.
- Town-first mode and a lifestyle quiz that seeds memory.
- Isochrone search by car or train.
- Saved searches and memory-aware alerts by email.
- **Three or more prefectures**, with the eval set extended to each.

### Scout agent, long-running

- **Inbox:** replies from towns are parsed (available dates, "sold", "please call", requests for documents) into structured events.
- **Event-driven re-planning:** a reply or a listing change updates the itinerary and creates proposals ("Town A offered March 3. Move the Day 2 route?").
- **Follow-ups** with limits: at most one polite follow-up per inquiry, never more.
- **Bookings with guardrails:** where a provider supports it, the agent prepares a booking and the user completes payment on the provider's own checkout. Spend caps and a second confirmation for anything involving money. Akiyomi never holds funds or card details.
- **Calendar sync** with Google Calendar (narrowest OAuth scope), replacing `.ics` export.
- **Permissions page:** per action type, choose "always ask", "ask once per Scout", or "never".

### Visit companion

- Mobile-friendly on-site inspection checklist that works offline.
- Photos upload into the report; a vision pass flags visible damage with confidence and "confirm in person".
- Post-visit debrief ("too dark", "loved the engawa") feeds memory.

### Quality and scale

- Review queue for low-confidence findings before they reach a paid report.
- Eval dashboard across stages, with a regression gate in CI.
- Cost budget per report and per Scout, with alerts.

## Not in 1.0

Document vault, contract and registry explainers, professional marketplace, renovation tracker, inheritor wizard, municipal tier, data API, co-buying pods, phone bridge. See [roadmap](roadmap.md#after-100).

## Success criteria

| Area | Target (placeholder; set after MVP data) |
| --- | --- |
| Revenue | First 50 paying customers; report price covers its cost at least 5× |
| Retention | 30% of Scouts are resumed within 14 days |
| Agent | ≥70% of inbound replies parsed correctly without human help |
| Safety | Zero unapproved external actions; zero money actions without second confirmation |
| Coverage | Three prefectures with eval targets met in each |
